一部可以在安卓手机上用的**离线创作应用**：写小说、写文章、写日记、排大纲、看文章，
每个模块独立的成就系统，加上创作时长 / 字数 / 速度 / 停笔间隔的统计，
以及阅读软件那样的**屏幕亮度调节**（含深色与护眼暖色）。
写作时还能从侧边拉出**功能库**（便签 / 大纲 / 排版 / 目标），另有游戏、音乐、计算器等消遣模块。
**所有数据只保存在这台设备上；唯一的联网功能是「阅读器 → 网址下载书籍」，需要你手动触发。**

## 功能总览（离线 / 联网）

这个应用**默认完全离线**：不登录、不上传、不统计，所有内容存在这台设备上。
只有一处功能会联网，而且必须你手动触发。

## 已知不足与限制（如实标注）

| 功能 | 不足 / 边界 |
| --- | --- |
| **续写辅助** | 是**本地启发式**（分析文风、人物、大纲方向后拼候选段落），**不是 AI 大模型**：本应用离线，没有语言模型接口。候选一定是你点选后才插入 |
| **协作合并** | 段落级合并，保证不覆盖、不丢内容、最终一致；但三个人在**同一毫秒**写同一段时，顺序无法保证唯一（真正的 CRDT 序列才能解决） |
| **隐私锁** | 是**应用内访问锁**，不是加密：密码存加盐哈希，界面与导出都挡住；但设备被拿到且对方懂技术（能连电脑调试），本地数据仍可能被读走 |
| **PDF 导入** | 只提取文本层；扫描版 PDF（图片）提取不出内容 |
| **MOBI** | HUFF/CDIC 压缩的 MOBI 暂不支持（普通 PalmDOC 压缩可以） |
| **农历与假期** | 农历表覆盖 1900–2100（已逐日与参考实现比对 73,384 天无差异）；**节气用近似公式，允许 ±1 天误差**；法定假期表精确覆盖 2024 / 2025 / 2026，其余年份按规则推算，**个别调休日可能不准**（只影响日历底色与注解，不影响数据） |
| **音乐音色** | 钢琴 / 电钢 / 吉他 / 贝斯用真采样（FluidR3_GM，CC BY 3.0，已署名），**鼓组仍是合成**（没找到许可清晰的打击乐素材）；音色手感因人而异，参数集中在 `js/view-music.js` 顶部常量，好调 |
| **翻页动画** | 卷曲翻页用 DOM + clip-path + transform 实现，**在低端机大量阴影可能掉帧**；没有做真实纸张纹理与光照模型 |
| **桌宠（已停用）** | 曾经做过一只 SVG 布偶猫桌宠，因观感不理想已**从应用里摘除**（源码保留在 `js/pet.js`、`js/view-pet.js`、`css/pet.css`，文件头标注「已停用」）。想启用就把 `index.html` 与 `sw.js` 里的三行引用加回去 |
| **书籍解析** | EPUB 支持常见排版；极个别带 DRM 的电子书无法导入（本应用不解 DRM，也不应解） |
| **平台** | 安卓 7.0+（APK）与桌面浏览器；iOS 未适配（PWA 可能可用但未测试） |
| **性能** | 单库几十 MB 文本仍可用；但整库备份导出在超大库上会占几秒 |

## 多用户与隐私（每个人的账号互相独立）

- **账号只在本机**：注册（昵称 / 头像 / 专属码）写在这台设备的存储里，**不会上传到任何服务器**，也不会出现在安装包或本仓库里。
  「专属码」是本机随机生成的一串代号，用于让朋友把你加进密友名单，**它不是账号密码，也无法用来登录任何服务**。
- **每个人各自一份数据**：换一个人使用，就在他的设备上注册他自己的账号；A 的作品、日记、导入的书都在 A 的设备上，
  B 看不到，开发者本人也看不到。本仓库**不包含任何人的作品、日记、导入内容或个人资料**（示例数据是代码里的演示文本，可在设置里一键清空）。
- **重新打开（重新登录）后照常加载**：所有内容保存在本机 **IndexedDB + localStorage**（双写兜底）。
  重开应用、重新注册或改昵称/头像都不会动你的内容；换设备请用「设置 → 导出整库备份（JSON）」，在新设备上「恢复备份」即可完整搬过去。
- **卸载 / 清浏览器数据会删掉本机内容**，所以设置页提供了「申请持久存储」与定期备份的建议。
- 本仓库不含签名密钥与服务器令牌（已在 `.gitignore` 中排除），发布前用 `node tools/prepare-github.js` 可复查一遍。

| **计算器** | 标准 / 科学 / 单位换算三种模式 · 记忆（MC/MR/M+/M−）· 角度弧度切换 · 历史记录 · 长度/重量/面积/体积/数据/时间/温度换算 |

两个游戏都支持**电脑键盘（方向键 / WASD）与手机触屏（滑动 + 屏上按键）**，
最高分记在本机，随整库备份一起走。音乐用 Web Audio 现场合成，**不需要任何音频文件**，因此完全离线、不增加安装包体积。

### 音乐：更多乐器 + 试音台

- **音色全部是现场合成的**，没有采样文件：
  钢琴用多谐波叠加（基频 + 2/3/4 次泛音）配自然衰减与收音尾巴，不再是最简单的单振荡器；
  电钢琴是载波 + 调制器的钟琴味；吉他是拨弦模型（起音噪 + 快速衰减包络）；
  贝斯低八度、起音结实、延音长；鼓组是底鼓（扫频正弦）、军鼓（噪声 + 鼓腔）、
  开/闭镲（滤波噪声）、桶鼓、拍手、牛铃等一次性音色。
- **每个乐器都有自己的可操作界面**：钢琴 / 电钢琴是带真实黑键几何的键盘（按键有按下的手感、
  标了音名与电脑键盘映射、可整体升降八度、可踩延音）；吉他与贝斯是**真实定弦的指板**
  （六弦/四弦 × 五品，每一格对应正确音高）；鼓组是**打击垫**，点下去会亮。
- **试音台**（`音乐创作 → 试音台`）：选乐器 → 在它的界面上弹 → 调 **音量 / 延音 / 明亮度**
  → 看电平表跳动，每个乐器还带一段内置示范乐句，用来快速听音色差别。

## 账号与状态（1.10.0）

应用完全离线，「注册」就是在这台设备上建一份**属于自己的档案**，用来在协作、日记和多人创作里表明身份。

| 内容 | 说明 |
| --- | --- |
| **昵称** | 协作署名、日记作者、参与者名单都用它；改了昵称，之后的消息就用新名字 |
| **头像** | 24 个表情头像任选，也可以从相册选图（压缩后存在本机，不上传）；不设头像就用昵称首字 |
| **专属码** | 形如 `SW-XXXXXX`，本机随机生成、可复制、可一键换新；朋友用它把你加进密友名单 |
| **状态** | 仿微信 / QQ：一句话 + 表情，可设「1 小时 / 今天 / 一周」时效，随时更新或清除 |
| **密友名单** | 记下常一起写的人（名字 + 专属码），协作时直接勾选参与者 |

状态显示在**个人页**、**各模块首页顶部的状态卡**，以及顶部栏的「我的」按钮上
（按钮显示状态表情，没注册时带一个红点提醒）。

入口：顶部栏最左边的人像按钮 → 「我的」。

| 位置 | 入口 | 显示 |

## 隐私锁

在任意作品（小说 / 文章 / 日记本 / 读物）的「更多」菜单里选「设为私密」，之后打开它需要密码。
入口在「娱乐 → 隐私锁」。

**挡住了哪些地方**（这几处都有回归测试 —— 缺一处就等于白锁）：

- 模块列表：只显示「私密作品 · 已上锁」，标题与简介都不出现
- 作品详情、章节写作页、日记本、读物正文
- **「继续写作」卡片**：不再显示私密作品的标题
- **全局搜索**：私密作品的标题、章节、大纲节点、正文全部不入结果

**安全边界（请务必知悉）**：这是「应用内访问锁」，**不是加密**。
密码只存加盐哈希、不存明文，界面与导出都挡住；但浏览器里的 JS 无法可靠地加密本地数据
（密钥同样存在这台设备上），如果对方懂技术、能把设备连上电脑调试，数据仍可能被读走。
忘记密码无法找回，只能清空数据。真正的加密需要每次打开都手动解密，会让自动保存明显变慢 ——
如果需要，我可以再做一档「真加密」模式。

## 联网下载书籍

「阅读 → 导入文章 → 网址下载」：填一个文件直链即可下载并导入，支持 TXT / EPUB / MOBI / PDF，
单本上限 96 MB。

实现上由**本机服务代取**（安卓壳里的 `LocalServer` 与网页版 `server.js` 都实现了 `/__fetch`）：
网页直接抓外部地址会被跨域策略拦死，走本机代理就没这个问题。只接受 `http/https`，其余一律拒绝。

> 需要「直链」：网页地址（`.html`）通常抓不到正文。部分站点会拒绝非浏览器请求。

## 协作与分享

入口在顶部栏的「更多 → 协作与分享」。三种「一起写」的方式：

| 方式 | 场景 | 怎么用 |
| --- | --- | --- |
| **协作室** | 同一个 WiFi | 一台设备点「开一个房间」拿到 6 位房间码，朋友打开你屏幕上的地址（形如 `http://192.168.x.x:8099`）→「输入房间码加入」 |
| **分享包** | 不在一起 | 选一部作品「生成并保存」，把文件用微信/QQ 发给对方，对方导入即自动合并 |
| **密友名单** | 常用的人 | 记下名字，加入时直接选；密友日记写起来更省事 |

### 为什么不会起冲突

合并是**段落级**的，规则可证明：

- 段落以「规范化文本的哈希」为身份 —— 同一段文字在两边是同一个 id
- 合并 = 两边段落的**并集**：谁都不会覆盖对方新增的段落
- 删除用**墓碑**记录，避免「我删了你又同步回来」
- 排序只用与顺序无关的依据（位置、时间、作者、id），
  所以 `merge(A,B)` 与 `merge(B,A)` 结果**完全一致** —— 两台设备不会各排各的

这些性质在 `tools/test-collab.js` 里有 31 项测试逐条验证（交换律、幂等、不丢内容、收敛性、删除语义）。

> **如实说明一个理论边界**：三个人在**同一毫秒**各写一段时，无中心服务器无法保证唯一的总顺序
> （这需要真 CRDT 序列才能解决）。但内容一段都不会丢、也不会互相覆盖 ——
> 这才是「不冲突」的实质。实际写作中三人时间戳不会相同，那时顺序完全确定。

### 多人日记

日记本可以设「共同记录人」。设了之后：

- 每条记录**署上作者**，卡片上直接显示
- 日历与当日面板可按人**筛选**
- 合并按「日期 + 作者」去重：同一天里各人的记录都保留，互不覆盖

### 技术实现

房间用 **HTTP 轮询（2 秒一次）** 而不是 WebSocket —— 安卓壳里的本机服务是手写 HTTP，
加 WebSocket 要重写协议栈；轮询对写小说这种交互密度完全够，而且断线重连天然简单。
房间只存在于内存里（临时凑一桌，不是云服务），12 小时无活动自动清理。

## 手机导入文件是怎么修的

手机上「选了文件却说没能导入」有两个成因，1.6.0 起逐步修好，1.7.0 又加了兜底：

1. **WebView 读不出 `content://` 文件**
   系统文件选择器返回的是 content URI，WebView 的 `FileReader` 在部分机型/文件管理器上读不出内容。
   现在壳里用 `ContentResolver` **直接把字节读出来**（base64 交给网页），彻底绕开这一层；
   同时补上了之前漏掉的 `takePersistableUriPermission`（持久化系统授予的读权限）。
2. **原生通道万一没应答，会自动回退**
   网页调原生通道后 **8 秒内没有任何回调就判定不可用**，立刻改用标准 `<input type="file">`，
   绝不会出现「点了没反应」。两条路都拿不到文件时，会把两种失败原因都报出来。
3. **导入管线曾经把二进制文件当文本读**
   `pickFile` 里那段「读不出就用 `file.text()`」的兜底，会在选完文件时就把第一个文件**按 UTF-8 解成文本**，
   EPUB / PDF / MOBI 会被解成乱码。现在统一**先读字节**，失败才退化为文本。

失败时的提示会给出**文件名、大小、MIME、扩展名**与卡在哪一步（读取 / 解析 / 提取为空），
并带「复制诊断信息」按钮。导入对话框里还有一个 **「文件导入自检」** 按钮，
会直接告诉你这台设备上原生通道是否就绪、系统选择器是否可用。

## 续写辅助（小说 / 文章）

写作页顶部栏的灯泡按钮 →「续写辅助」。它照着你已写的节奏、人物与**本章大纲方向**，
给出几个能接着往下写的段落，点一个插入正文末尾。

> **如实说明：这不是 AI 代写。** 本应用离线，当前环境也没有语言模型接口，
> 所以它做的是**本地启发式续写**：从你的正文里提取人物名与句式节奏，
> 从大纲取「接下来该发生什么」，再按「动作推进 / 对白承接 / 心理描写 / 场景转场」
> 四类骨架套用你的句式，生成候选段落。
> 它的定位是**打破卡壳的起头器** —— 给你几个能往下接的句子，而不是替你写完一部小说。
> 生成结果一律先给候选，由你挑一个改一改再用。

**从外部导入并续写**：「更多 → 新建 → 导入并续写」，导入别人的文章 / 小说
（或你自己的旧稿），自动切章后直接打开续写面板。

**人物识别**用的是保守策略：只认「常见姓氏 + 1 字」且**后接动作/说话类动词**，
或同一个名字重复出现。宁可漏掉 3 字名，也不造出假人物 —— 因为假名字会直接写进候选句子。

## 多语种

设置页（顶部栏 📊 → 设置）可切换 **简体中文 / English / 繁體中文**，
**切换是就地生效的：不刷新页面**，也不会打断你正在写的东西。

实现方式是**运行时词典替换**而不是改写上千处文案：

- 词典的 key 就是源码里的中文原文，一眼能核对
- 挂 MutationObserver，新渲染的节点、**以及后写入的文字与 placeholder / aria-label** 都会自动翻译
- **只替换「整段完全匹配」的文本** —— 你写的作品内容永远不会被翻译
  （阅读正文、日记正文、便签、大纲节点、协作聊天都单独加了保护）
- 翻译过的节点会记下原文，切回中文时逐字还原，所以不用重载页面
- 查不到词条就显示中文原文（宁可显示中文，也不要出现乱码键名）

词典分两层：

| 文件 | 内容 |
| --- | --- |
| `js/i18n.js` | 核心逻辑 + 内置常用词条 + **数字模板**与「简→繁」字表 |
| `js/i18n-extra.js` | 自动生成的扩展词典（英文 373 条 / 繁体 422 条 / 模板 130 + 116 条） |

「小字」也能翻，靠三层兜底：

1. **数字模板**：`共 12 节`、`1234 字`、`第 3 章`、`已读 45%` 这类「词 + 数字」的句子，
   先把数字挖成占位符再查表，所以数字变了照样能翻
2. **混排句子分段**：`时长 0 min · 目标 1,000 字` 按 `·`、`，`、`/` 拆开逐段翻再拼回去
   （至少两段命中才动手，避免把用户句子翻掉一半）
3. **运行时拼的整句**：`连续创作 3 天 · 累计 2 小时` 这种在源码里拼出来的句子，
   写法改成 `U.pick(中文整句, 英文整句)`，繁体再走字表转换；
   日期、时长、相对时间（`刚刚 / 昨天 / 9月24日 周四`）也全部按语言输出

词条是**扫描出来的**，不是拍脑袋补的：

| 工具 | 作用 |
| --- | --- |
| `node tools/i18n-scan.js` | 把 60+ 个界面（含每个弹层）跑一遍，列出还剩下哪些中文 |
| `node tools/i18n-strings.js` | 从源码里捞「界面会出现但扫描没走到」的文案（空状态、罕见提示） |
| `node tools/i18n-coverage.js 8099 en` | 给出某语言的覆盖率（en 只剩用户内容；zh-TW 缺口 0） |
| `node tools/i18n-merge.js` | 把 `tools/i18n-frag-*.json` 合并成 `js/i18n-extra.js` |

繁体不是简单字形转换：`i18n.js` 里有一张**用词表**（导入→匯入、设置→設定、文件→檔案、
搜索→搜尋、保存→儲存、默认→預設、软件→軟體…），自动补繁体与运行时拼句都会过一遍，
人工翻译过的词条以人工稿为准。

## 导入体验

导入大文件时界面会**显示加载动画并暂时锁住操作**：

- 立刻弹出遮罩：转圈 + 当前阶段（读取 → 解析 → 整理章节 → 保存）+ 进度条
- 遮罩期间**任何点击都无效**，避免用户以为卡住了乱按、结果跳走或误删
- 超过 3 秒会提示「已处理 N 秒，大文件会慢一些」
- 完成后自动撤掉遮罩并打开刚导入的内容

拦截用**捕获阶段**实现：只在遮罩上 `stopPropagation` 是不够的 ——
事件到达目标元素（比如别的标签按钮）时它自己的处理函数照样会跑。

导入过程也在重活之间让出主线程（`yieldToUI`），所以动画真的能转，不是冻住的图片。

## 打开一本书为什么不卡（1.9.0）

以前打开读物是**一次性把整本书的正文都塞进 DOM**：一本 300 章的小说要一次布局几十万字，
手机上点开要等好几秒；而「继续阅读」还原位置时，容器又有 `scroll-behavior: smooth`，
于是会**从第一页平滑滚动到第 200 章**，一路把沿途每一章都排版一遍 —— 这是「打开书很慢、
一直在加载」的真正原因。

现在改成三步渐进渲染：

1. **章节标题全部先建**（很便宜）—— 进度、目录、跳转都靠这些锚点
2. **首屏只渲染当前这一屏附近**的几章，其余放「估高占位块」把滚动条撑到全书长度；
   占位高度用首屏几章的真实排版自动校准
3. 剩下的交给 `IntersectionObserver`：滚到哪渲染到哪；占位块换成正文时，
   如果它在视线之上，按高度差把滚动位置补回来，正在读的几行不会被顶走

定位一律**瞬时**（临时关掉平滑滚动），所以还原到第 201 章是瞬间到位，不会滚过整本书。
进度改用**字符位置**计算（已读字符 / 全书字符），占位块的估高误差不会让百分比乱跳。

用 `node tools/bench-reader.js` 可以复现（300 章 / 250 KB 的合成书）：

| 指标 | 老办法（一次渲染全书） | 现在 |
| --- | --- | --- |
| 打开时的同步渲染 | 布局 200 ms+（真机更慢） | **9–12 ms** |
| 打开后 DOM 里排好版的章节 | 300 章 | **3–4 章** |
| 从第 201 章继续读 | 平滑滚过全书 | **5 ms 到位，只排版 5 章** |
| 滚到全书末尾 | — | 只排版 8 章，进度 100% |

## 返回键（安卓）

返回键不再像浏览器那样「每一步都回退」，而是像原生应用一样**一层一层退**：

- 有弹层先关弹层（弹层也不会再跨页面残留）
- 页面栈只记「层」：写作页里换章节、阅读器里换小节、日记里换日期都只是**替换栈顶**，
  不会越堆越深
- 从写作页返回 → 回到所属模块；从工具页返回 → 回到来源页
- 换底部标签会重置页面栈，此时再按返回键就是**退出应用**（第一次按提示「再按一次返回键退出」，
  第二次才真的退出）

实现只有一份逻辑：`UI.hardwareBack()`。安卓壳的 `onBackPressed` 把按键交给网页里的这个函数，
在浏览器里则表现为应用内的「返回」按钮。

| **多种翻页方式** | 连续滚动 / 整页翻页（点左右两侧或上下轻扫，带翻页动画）/ 滑动翻页（横向手势 + 过渡动画）；键盘 ← → 、PgUp/PgDn 翻页，Esc 唤回工具栏。三种模式下的进度、书签、目录跳转都正常 |
| **书签** | 点书签按钮会**点亮**（当前位置已有书签就是实心，再点取消）；章标题左侧出现丝带标记（Markdown 导入的还能精确到段落）；目录里带书签的行有独立标记，右侧细长进度条上也有书签刻度，可点击跳章 |
| **收藏爱心** | 每本书名旁（双列时在封面角上）都有爱心，点一下收藏 / 取消；书架另有「收藏」筛选 |
| **章节数与字数** | 章节数一律显示（0 章也照实显示）；字数**一万以上自动用「万」**（英文界面用 k/M） |

顺手修掉的两个老问题：切走后旧阅读实例的滚动尾巴会把同一本书的进度写成 100%；目录跳到中间章节时用平滑滚动会被占位块换正文顶偏（跳第 6 章结果落在第 12 章）——现在跳转一律瞬时并在下一帧校正。

性能没有回退：ools/bench-reader.js 首屏同步渲染 9–16 ms、只排版 4 章 / 待排版 296 章，滚到末尾仍是 100%。

## 快速开始（网页版）

**双击桌面上的「selfwriting 创作」即可** —— 它会自动在后台启动本地服务并打开应用
（服务独立运行，关掉那个窗口不影响使用）。

桌面快捷方式由下面这条命令创建（已执行过；换机器或删掉后再跑一次）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-shortcuts.ps1
```

会生成三个快捷方式（图标取自 `assets/icon.ico`）：

| 快捷方式 | 作用 |
| --- | --- |
| selfwriting 创作 | 启动本地服务 + 打开应用 |
| selfwriting 手机安装 | 显示手机访问地址（装 APK / 加桌面用） |
| selfwriting 停止服务 | 关闭后台服务 |

不想用快捷方式也可以手动：

```powershell
node server.js 8099     # 只启动服务
node launcher.js        # 启动并打开应用
node launcher.js phone  # 显示手机访问地址
node launcher.js stop   # 停止服务
node launcher.js status # 查看运行状态
```

- 电脑上打开 <http://127.0.0.1:8099/>
- 手机上（同一 Wi-Fi）用「selfwriting 手机安装」里给出的地址打开，
  Chrome 菜单 →「安装应用 / 添加到主屏幕」，之后断网也能用
- 想要 `.apk` 安装包：见上面的「安卓安装包」或 [`ANDROID.md`](ANDROID.md)

> 直接双击 `index.html` 也能打开，但 `file://` 下浏览器不允许本地数据库，
> 数据只能临时保存在内存里，**请用上面的本地服务器方式**。
> 首次进入点「看看示例数据」可以立刻看到各模块的样子（随时可在设置里清空）。

## 五大创作模块

### 1. 小说
- 一本书分**章**，一章还可再分**小节**，各自独立创作互不干扰
- 写正文时顶部常驻「**本章大纲**」面板：关联到本章/本节的大纲节点就在眼前，
  可以边写边改文字、改颜色、加重点，改完立刻同步回大纲模块（双向实时）
- **实时字数** + **自定义章节字数目标**：状态条显示百分比进度，达标时提示
- 章节上下移动、重命名、单章导出、整本导出
- 可标记完结，完结会触发对应成就

### 2. 大纲
- 树状结构，任意层级；**颜色区分分支**（8 色板，可一键继承给整条子分支）
- **重点标记**：★ 重点节点在各处高亮，还能「只看重点」过滤
- 节点可**关联到具体章节或小节**，关联后在写作页实时显示；点关联标签直接跳到正文
- 节点详情（内容 + 备注 + 颜色 + 重点）、复制整支、升级为上级、上移下移、删除
- 支持导入大纲文本（用缩进表示层级，`★` 表示重点），导出 TXT / Markdown / 复制为列表

### 3. 文章
- 长文、随笔、散文的单页创作，同样有实时字数与字数目标
- 标签、导出 TXT / Markdown、复制全文、可直接导入外部文本成篇

### 4. 日记
- **日历视图**：月历按当天记录多少显示深浅，点任意日期补记
- **日记 / 周记 / 月记 / 自定义间隔**四种记录本：
  - 周记自动汇总本周记录，月记自动汇总当月，自定义间隔按「最近 N 天」汇总
  - 自定义间隔会提示「该记录了 / 距下次还有几天」
- 心情、天气、标签、**插入图片**（自动压缩后存入本机数据库）
- 支持从 TXT / Markdown 导入日记，自动识别日期行按天归档

### 5. 阅读器
- 导入 TXT / Markdown（自动识别「第 X 章 / # 标题」分章，也可当作整篇）
- 连续滚动阅读、目录跳转、进度百分比、书签、本书内搜索
- 字号、行距、衬线字体、深色、护眼暖色、屏幕亮度
- 与创作模块互不干扰，只统计阅读时长与阅读字数

### 6. 搜索 / 导入导出
- 全局搜索：作品名、章节标题、正文内容、大纲节点、日记、读物章节
- 导出：条目 TXT / Markdown、大纲文本、单章、**整库 JSON 备份**（含图片）
- 导入：文本导入为小说 / 文章 / 日记 / 读物；备份**合并导入**或**覆盖导入**
- 回收站：删除的东西可以恢复一次

## 成就系统（各模块独立）

| 模块 | 成就规则 |
| --- | --- |
| 小说 | **每 10 万字**一个成就（10 万 / 100 万 / 1000 万 / 1 亿），另加单本长篇（10/20/50/100 万字）、章数（10/30/100/300 章）、完结本数、章节达标次数 |
| 文章 | **每 1 千字**一个成就（1 千 / 1 万 / 10 万 / 100 万），另加单篇字数与篇数（1/5/10/30/50/100/300 篇） |
| 日记 | 每 1 千字成就 + **记录天数**（1/7/30/100/365/1000 天）+ **连续记录**（连续三天、**连续一周**、两周、**一个月**、百日、一年）+ 周记/月记/自定义间隔篇数 + 插图张数 |
| 大纲 | 节点数（10/30/100/300/1000）、重点标记数、与章节的联动数、使用的分支颜色数 |
| 阅读 | 读完册数、阅读字数、阅读时长 |
| 综合 | **活跃天数**（1/3/7/14/30/100/365）、**活跃周数**、**月度成就**、**年度成就**、累计字数、累计时长、每日目标达成天数 |

成就只增不减，解锁时弹出提示，成就墙里能看到每一条的进度条与解锁时间。

## 统计

- **创作时长**：自动计时，停笔超过设定秒数（默认 45 秒）即结束当前写作段；切后台会立即结算
- **字数**：分模块统计，另有每日、近 30 天趋势柱状图与 15 周活跃热力图
- **创作速度**：字/小时，按模块与按天排行，记录历史最快速度
- **滞留最长间隔**：最长停笔间隔（起止日期）、当前已停笔天数、连续创作天数
- 其它：最长单次写作、单日最高字数、写作段流水（时间段 / 字数 / 速度）

## 界面与阅读体验

- 极简纸感设计，底部五个标签：书架 / 日记 / 大纲 / 阅读 / 统计
- **亮度调节**：顶栏太阳图标 → 拖动亮度条（20%–100%，等同阅读软件的调暗效果）

- 每日字数目标、新章节默认字数目标、写作段停顿判定都可自定义
- 数据自动保存：输入即写入本机（防抖落盘），切后台/关闭页面立即保存

## 数据与隐私

- 作品与统计存在 **IndexedDB**，并同步一份到 **localStorage** 作为兜底；
  日记插图压缩后单独存在 IndexedDB 的 images 表
- 全程**没有任何网络请求**，没有账号、没有云同步；换机请用「设置 → 导出整库备份」
- 清理浏览器数据 / 卸载应用会删除内容，建议定期备份
- 「设置 → 申请持久存储」可降低系统自动清理缓存的概率
